Journey Telemetry

Data-to-Insight Latency

How long a user waits from linking an account to having data fetched, insights computed, and spending categorized — read from the ClickHouse journey-tracking pipeline.

Method. A scheduled job mints a channel token per tenant and calls /pfm/api/v2/journey/{delay-stats/snapshot, analytics-pipeline, deposit-categorization-stats, webhook-delivery-stats, fi-notification-errors}. Metrics are pre-aggregated in ClickHouse as avg / median / p95 over 15-minute buckets. Tenant is resolved from the JWT, so each client is queried separately — there is no cross-tenant query.

Reading the numbers. The §2 funnel is the live snapshot (last 15 min) — what one user linking an account right now actually waits. The 24-hour tables include overnight BATCH_INITIATED refresh and backlog drain, where a still-pending task's clock keeps running; those averages are not single-user latency. Both views are shown deliberately.

Anonymised. Client identities, hostnames and tenant ids are stripped before publishing; the fetcher aborts rather than commit a payload where any identifying term survives scrubbing.
